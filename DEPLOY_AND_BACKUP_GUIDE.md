# Руководство по резервному копированию, восстановлению и деплою ТМ «Сибсыр»

Данное руководство описывает работу встроенной системы резервного копирования и восстановления данных сайта `sibsir.ru` для безопасного переноса и развертывания (деплоя) на хостинге или сервере.

---

## 1. Что входит в резервную копию

Резервная копия упаковывается в единый ZIP-архив с автоматическим манифестом целостности (`manifest.json`):

1. **Каталог продукции с фотографиями:**
   - Категории (`shop.Category`)
   - Товары с ценами, фасовкой и характеристиками (`shop.Product`)
   - Акции и спецпредложения (`shop.Promotion`)
   - Промокоды и купоны (`shop.PromoCode`)
   - Отзывы покупателей к товарам (`shop.Review`)
   - Все изображения каталога (папки `media/products/`, `media/categories/`)
2. **Списки заказов:**
   - Заказы физических и юридических лиц (`shop.Order`)
   - Детальные товарные позиции каждого заказа (`shop.OrderItem`)
3. **Клиенты и зарегистрированные пользователи:**
   - Учетные записи (`auth.User`)
   - Профили клиентов с типами (физ/юрлицо), реквизитами (ИНН, КПП, ОГРН, банк, расчетный счет), телефонами и адресами (`accounts.UserProfile`)
   - Заявки клиентов на обратный звонок (`main.CallbackRequest`)
   - Заявки оптовиков на оптовый прайс-лист (`main.WholesalePriceRequest`)
4. **Статьи блога с иллюстрациями:**
   - Статьи о сыроделии, рецепты и советы (`articles.Article`)
   - Изображения статей (`media/articles/`)
5. **Настройки сайта и сопутствующий контент (для полноценного деплоя):**
   - Глобальные настройки бренда, контакты, телефоны, логотип (`main.SiteSettings`)
   - Брендинг и иконки (`media/branding/`, `media/social_icons/`)
   - Способы доставки и тарифы (`main.DeliveryMethod`)
   - Способы оплаты (`main.PaymentMethod`)
   - Сертификаты качества ГОСТ (`main.QualityCertificate`)
   - FAQ (вопросы и ответы, категории) (`main.FaqCategory`, `main.FaqItem`)
   - Преимущества завода и таймлайн истории (`main.ProductionFeature`, `main.CompanyTimeline`)
   - Отделы компании и соцсети (`main.ContactDepartment`, `main.SocialLink`)
   - Информационные SEO-страницы (`main.Page`)

## 2. Способ 1: Управление через веб-интерфейс Админ-панели (без терминала)

Для удобства администраторов создан графический веб-интерфейс:

1. Войдите в панель управления: `https://ваш-домен/admin/` под учетной записью суперпользователя.
2. В верхнем меню выберите **«Настройки» → «Резервное копирование и деплой»** (или нажмите кнопку «Бэкап и деплой» на главном экране дашборда).
3. **Создание бэкапа:**
   - Выберите разделы, которые нужно включить (по умолчанию выбраны все).
   - Оставьте галочку «Включить фотографии товаров и медиафайлы».
   - Нажмите **«Создать и сразу скачать .ZIP»** (для сохранения копии на компьютер) или **«Создать и сохранить на сервере»**.
4. **Восстановление данных:**
   - Выберите вкладку «Загрузить файл с компьютера» (перетащите ранее скачанный .zip) или «Выбрать архив с сервера».
   - Выберите опции:
     * *«Распаковать и обновить фотографии»* — восстановит картинки в `media/`.
     * *«Очистить существующие таблицы перед импортом (Режим чистого деплоя)»* — включите эту опцию, если хотите полностью заменить старую базу данных актуальной. Учетные записи администраторов (`is_superuser`) при этом безопасно сохраняются!
   - Нажмите **«Запустить восстановление»**.

## 3. Способ 2: Консольные команды Django (Management Commands)

Для автоматизации деплоя, сценариев CI/CD и работы через SSH-терминал реализованы стандартные команды Django:

### Создание резервной копии (`backup_data`)

```bash
# 1. Посмотреть текущую статистику базы и медиафайлов
python manage.py backup_data --stats

# 2. Создать полный бэкап (все данные + все фото в ZIP)
python manage.py backup_data

# 3. Выгрузить только каталог товаров с фотографиями
python manage.py backup_data -i catalog

# 4. Выгрузить только заказы и клиентов
python manage.py backup_data -i orders,users

# 5. Выгрузить только статьи
python manage.py backup_data -i articles

# 6. Легкий бэкап только базы данных (без картинок)
python manage.py backup_data --no-media

# 7. Сохранить в конкретный файл с описанием
python manage.py backup_data -o /tmp/my_backup.zip -d "Перед обновлением цен"
```

Архивы по умолчанию сохраняются в папку `mysite/backups/`.

---

### Восстановление данных (`restore_data`)

```bash
# 1. Посмотреть список доступных архивов на сервере
python manage.py restore_data --list

# 2. Проверить архив перед восстановлением (Dry-Run, без изменений в БД)
python manage.py restore_data --dry-run

# 3. Восстановить самый свежий бэкап из папки backups/
python manage.py restore_data --yes

# 4. Восстановить конкретный архив
python manage.py restore_data mysite/backups/backup_sibsir_all_20261103_084541.zip --yes

# 5. Чистый деплой (очистить таблицы каталога, заказов и клиентов перед накатом)
python manage.py restore_data backup_sibsir_all_20261103_084541.zip --clear --yes

# 6. Восстановить только каталог товаров с картинками
python manage.py restore_data backup_sibsir_all_20261103_084541.zip -i catalog --yes

# 7. Восстановить только базу без перезаписи файлов картинок
python manage.py restore_data --no-media --yes
```

## 4. Способ 3: Быстрые скрипты для Windows и Linux

В корне репозитория подготовлены готовые скрипты:

### На локальном компьютере (Windows PowerShell):
- `.\backup.ps1` — создать полный бэкап
- `.\backup.ps1 -CatalogOnly` — только каталог и фото
- `.\backup.ps1 -NoMedia` — только база данных
- `.\restore.ps1` — восстановить последний бэкап
- `.\restore.ps1 -Clear -Yes` — восстановить с очисткой таблиц
- `.\restore.ps1 -List` — список бэкапов

### На сервере хостинга (Linux / SSH):
- `./backup.sh` — создать резервную копию
- `./backup.sh --catalog-only` — только каталог
- `./restore.sh` — восстановить последний архив
- `./restore.sh --clear --yes` — чистый накат
- `./deploy.sh` — стандартный деплой (pull, migrate, collectstatic, touch passenger_wsgi.py)
- `./deploy.sh --restore` — деплой с автоматическим восстановлением последнего бэкапа
- `./deploy.sh --clean-restore` — деплой с очисткой таблиц и накатом свежих данных

## 5. Пошаговый сценарий переноса данных и первого деплоя на хостинг Timeweb

### Шаг 1: Создание бэкапа на машине разработки
Запустите команду:
```powershell
.\backup.ps1 -Description "Релиз для продакшена"
```
Архив сохранится в `mysite\backups\backup_sibsir_all_ГГГГММДД_ЧЧММСС.zip`.

### Шаг 2: Перенос файлов на хостинг
Перенесите код проекта и архив бэкапа на сервер Timeweb (по SFTP, SCP или Git):
Путь на хостинге Timeweb: `/home/d/dpitstudio/sibsir.ru/public_html/`

Положите архив в папку `mysite/backups/`.

### Шаг 3: Накат данных на хостинге через SSH
Подключитесь по SSH к серверу и выполните:
```bash
cd /home/d/dpitstudio/sibsir.ru/public_html
chmod +x deploy.sh backup.sh restore.sh

# Запуск деплоя с накатом данных и картинок:
./deploy.sh --clean-restore
```

Скрипт автоматически:
1. Применит все миграции Django (`migrate`).
2. Очистит устаревшие таблицы и накатит товары, картинки, заказы, клиентов и статьи из бэкапа.
3. Соберет всю статику админки и сайта (`collectstatic`).
4. Перезапустит веб-сервер Passenger WSGI (`touch passenger_wsgi.py`).

## 6. Настройка автобэкапа по Cron (на хостинге)

Чтобы ежедневно в 03:00 ночи автоматически создавался бэкап сайта, добавьте в `crontab -e`:

```cron
0 3 * * * /home/d/dpitstudio/sibsir.ru/public_html/backup.sh > /home/d/dpitstudio/sibsir.ru/public_html/mysite/backups/cron_backup.log 2>&1
```
